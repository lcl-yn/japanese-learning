# 单词本添加单词

**日期**：2026-11-18  
**状态**：已确认  
**范围**：开发时在单词本追加一条词到清单指向的课次 JSON，并立刻进入内存词库。

## 背景与目标

单词本目前只读 `public/data/words`。课文和语法已经能在 `npm run dev` 里经 Vite 接口写回文件，打包后的静态站没有这些接口。

目标：单词本增加「添加单词」。填写中文、假名、手写，以及可选的说明、词性，并确定落到哪一课。提交后把这一条追加到对应 JSON 末尾，单词本和之后的练习抽词都能用到它。

## 已确认决策

| 项 | 选择 |
|----|------|
| 何时可写 | 只在 `npm run dev`。打包后没有按钮，也没有接口 |
| 写到哪 | 当前册、单元、课都是具体课时，写入这一课。任一层是「全部」时，在对话框里再选，选项不含「全部」 |
| 课的范围 | 与单词本课次下拉相同，包含带词表的单元页（如「单元末-词语之泉」） |
| 必填 | 中文、假名、手写。说明、词性可空 |
| 重复 | 同一课已有相同中文和假名时，仍然追加 |
| 写入方式 | `PUT /__words`。服务器按清单定位文件，只在数组末尾追加一条 |

## 交互

按钮放在单词本工具栏筛选区末尾、三个显示开关之前，文案为「添加单词」。用 `import.meta.env.DEV` 控制，生产构建不渲染。

点开对话框，标题「添加单词」。

- 册、单元、课都已是具体值时，对话框用清单里的名称标出这三层，不能改。表单只填词条。
- 任一层是「全部」时，对话框提供册、单元、课三个下拉，没有「全部」。已经选好的层预填。册未选时，单元和课不可选；单元未选时，课不可选。改册会清空单元和课，改单元会清空课。课的选项与单词本相同：该单元的课，加上 `wordPages` 列出的词表页。
- 字段为中文、假名、手写、说明、词性。前三项去掉首尾空白后不能为空。说明和词性可以空。
- 只有点「提交」才发送。输入法组字中的回车不提交。「取消」或关闭对话框不写文件，再次打开是空表单；位置仍按当时的筛选决定。
- 必填为空时标在字段上，不发请求。
- 成功后提示「已添加」，关闭对话框并清空。不改当前册、单元、课筛选。当前筛选盖得住这条词时，表格马上多一行。
- 失败时对话框保持打开，已填内容保留，并用 `ElMessage.error` 显示接口返回的原因。请求没有返回原因时，提示「添加失败」。

## 请求与落盘

客户端 `PUT /__words`，请求体：

```json
{
  "bookId": "beginner-upper",
  "unit": 1,
  "lesson": 1,
  "cn": "大学生",
  "jp": "だいがくせい",
  "jp_write": "大学生",
  "describe": "",
  "part_of_speech": "名"
}
```

`vite/wordSavePlugin.ts` 只在 Vite `serve` 时注册。处理步骤：

1. 五个文本字段必须是字符串，并去掉首尾空白。中文、假名、手写为空则 400。说明、词性空着写成 `""`。
2. 读 `public/data/words/manifest.json`。按 `bookId`、`unit` 找到单元后，先在 `lessons` 里按 `lesson` 匹配；没有再在带词表的 `pages` 里按 `lesson` 匹配。都没有则 400，不写文件。
3. 文件路径只用清单里的 `file`。它必须是相对路径，不能以 `/` 开头，也不能包含 `..`。解析后的绝对路径必须落在 `public/data/words` 下面，否则 400。
4. 磁盘上没有该文件时，从空数组开始。文件存在时必须能解析成 JSON 数组，否则 400，不改文件。
5. 在数组末尾追加一个对象，且只有 `cn`、`jp`、`jp_write`、`describe`、`part_of_speech`。不写 `bookId`、`unit`、`lesson`。已有条目原样保留，不补字段。
6. 整份数组用 4 空格缩进写回，末尾一个换行。同一进程内按请求顺序读写，避免两次提交互相覆盖。
7. 成功响应 `200`，正文 `{"ok":true}`。失败响应 `400`，正文 `{"message":"具体原因"}`。原因包括：必填为空、清单里没有这一课、路径不合法、词表无法解析、词表不是数组、写入失败。

## 内存

成功后不重新请求整份词库。Store 把这一条推进 `allWords`，并带上本次的 `bookId`、`unit`、`lesson`。

已经抽好的练习题保持不变。下次从这一课抽词时可以抽到新词。不修改 `wordErrorCounts`。

## 代码位置

- 按钮和对话框留在 `src/views/WordsView.vue`。
- 校验、按清单定位文件、把一条词追加进数组，放在 `src/utils/wordAppend.ts`，并配 `src/utils/wordAppend.spec.ts`。插件和页面都调用这些函数。
- 浏览器里的 `PUT` 放在 `src/services/wordSave.ts`，成功后调用 store 的追加方法。
- `vite.config.ts` 在开发插件列表里注册 `wordSavePlugin`。
- 同一任务里更新 `.cursor/rules/project-map.mdc`：单词本在开发时可以添加单词，经 `PUT /__words` 追加到清单指向的课次 JSON。

## 测试

纯函数单测要覆盖：

- 中文、假名或手写在去空白后为空时拒绝。
- 清单中不存在的册、单元或课被拒绝。
- 课次文件优先于同课号的词表页；只有词表页时能定位到该 `file`（如词语之泉）。
- 路径含 `..` 或越出 `public/data/words` 时拒绝。
- 现有内容不是数组时拒绝，且不产生可写结果。
- 正常追加后只在末尾多一条，新对象只有五个字段；说明、词性空白写成 `""`。
- 已有条目的字段不被改写。

界面在 `npm run dev` 里实际提交一条：对应 JSON 末尾多出这条，当前筛选能看到它；关掉开发服务器后的构建页面没有「添加单词」按钮。

## 不做

- 修改或删除已有词。
- 打包后的持久化，或写入清单中不存在的新课。
- 重复词提示。
- 提交后自动改筛选，或重抽当前练习题。
