# Japanese Vocabulary Confusion Engine
# 日语单词混淆题生成算法规范

- **文档名称**：日语单词高混淆度四选一生成算法规范
- **英文名称**：Japanese Vocabulary Confusion Engine
- **算法标识**：JP-VCE
- **版本**：V1.0
- **用途**：日语单词记忆测试、单词辨析、四选一练习
- **适用对象**：AI 编程模型、后端开发人员、算法模块

---

# 1. 项目背景

## 1.1 需求背景

日语学习过程中，用户需要通过测试判断自己是否真正掌握某个单词。

传统四选一题目通常采用随机抽取方式生成三个错误选项，这种方式存在以下问题：

1. 错误选项与正确单词完全无关，用户无需思考即可排除。
2. 选项之间差异过大，无法测试用户真实的记忆水平。
3. 无法针对日语单词发音、假名结构以及词义特点生成干扰项。
4. 无法针对用户长期学习中出现的错误进行个性化训练。
5. 题目难度无法有效控制。
6. 随机生成的选项缺乏统一的质量评价标准。

因此，本系统需要建立一套专门用于日语单词测试的高混淆度题目生成算法。

---

# 2. 核心目标

系统根据指定的目标单词，自动生成一组四选一测试题。

每道题必须满足：

- 1 个正确答案
- 3 个错误答案
- 所有选项均为真实、合法的日语单词
- 错误选项具有一定的混淆价值
- 不允许明显无关的低质量干扰项
- 不允许重复选项
- 不允许出现多个正确答案
- 支持难度控制
- 支持用户学习记录和个性化混淆
- 支持后续扩展单词、短语、句子等学习形式

算法核心原则：

> 不是寻找随机错误答案，而是寻找用户最有可能混淆的真实单词。

---

# 3. 题目类型定义

## 3.1 V1题型

V1仅支持：

**日语单词 → 四个候选单词 → 选择正确单词**

例如：

目标单词：

| 属性 | 内容 |
|---|---|
| 日语 | かいしゃ |
| 汉字 | 会社 |
| 中文 | 公司 |
| 词性 | 名词 |
| 读音 | かいしゃ |

生成的选项可以是：

| 选项 | 单词 | 中文释义 |
|---|---|---|
| A | 会社 | 公司 |
| B | 会話 | 对话 |
| C | 階段 | 阶段 |
| D | 開始 | 开始 |

其中：

- 会社：正确答案
- 会話：读音结构接近，存在音形混淆
- 階段：部分发音相似
- 開始：词形及发音存在一定关联

以上仅为混淆类型示意，实际候选必须通过算法评分、词库校验及质量过滤后才能使用。

## 3.2 手写选假名

手机单词本考试使用这一题型，不使用 3.1 的「四个真实单词」。

题面：

- 题干是目标词的日语手写。手写为空时用假名本身。
- 四个选项都是假名。一个是目标词的读音，三个是干扰读音。
- 干扰读音可以不是词库里的词。当前词库不够为每个目标词提供三个既真实、又读音极近的词，若仍要求「必须来自词库、凑不齐就不出题」，这一题型会经常出不来。

干扰项仍然不能随便抽，也不能拼出无法切拍的字符串。生成只允许下面这些细微变化，每次只动一点：

- 拗音：きゅ / きょ / きゃ，以及 きゅ / きゆ 这种一拍和两拍的差别
- 长音：きゅ / きゅう
- 促音：有っ和没有っ
- 清浊音、半浊音：か / が，は / ば / ぱ
- 同一行里相邻的元音： ka 只走到 ki，不跳到 ko

每个干扰项记下规则来源，并用第 7 节的发音相似度 P 和假名结构相似度 K 打分。这一题型没有词义和作答历史，S 与 M 不参与；权重按原来的 0.40 和 0.25 归一成：

```text
ConfusionScore = 0.615 * P + 0.385 * K
```

P 仍按第 7.2 节的拍编辑距离公式计算，不用整串字符距离代替拍。

组合仍要做：三个干扰项至少来自两种规则，优先混淆分高、规则不重复的一组，再打乱选项顺序。分数从 0.72 往下看到 0.30。降到 0.30 仍不够三个时，对已有候选再做一次上述变化来补齐。补齐用的仍是这些规则，不用无关假名。

因此第 8.1 节「候选必须在词库中」、第 19 节第 3、4、11 条、第 20 节「候选不足则失败」，只约束 3.1。手写选假名以本节为准。

# 4. 算法总体架构

整个题目生成过程分为以下阶段：

```text
指定目标单词
      |
      v
目标单词合法性校验
      |
      v
目标单词特征解析
      |
      v
干扰候选生成
      |
      +---- 发音相似候选
      |
      +---- 假名结构相似候选
      |
      +---- 词义相关候选
      |
      +---- 同类词候选
      |
      +---- 用户历史错误候选
      |
      v
候选合法性过滤
      |
      v
候选混淆度评分
      |
      v
难度过滤
      |
      v
干扰项组合优化
      |
      v
重复题控制
      |
      v
正确答案与错误选项混合排序
      |
      v
最终题目质量校验
      |
      v
生成四选一题目
```

任何阶段失败，都不得直接使用随机单词补足。

# 5. 单词特征模型

算法必须对每个日语单词建立统一的特征模型。

## 5.1 VocabularyFeature

每个单词至少应包含以下属性：

| 属性 | 说明 |
|---|---|
| wordId | 单词唯一标识 |
| kana | 假名读音 |
| kanji | 汉字表达 |
| meaning | 中文释义 |
| meanings | 多义词释义列表 |
| romaji | 罗马音 |
| phonemes | 音素序列 |
| moraUnits | 拍音序列 |
| moraCount | 拍数 |
| wordLength | 假名长度 |
| wordType | 单词类型 |
| partOfSpeech | 词性 |
| semanticCategory | 语义类别 |
| accentPattern | 音调信息，可选 |
| isLongVowel | 是否包含长音 |
| isGeminate | 是否包含促音 |
| isNasal | 是否包含拨音 |
| isContracted | 是否包含拗音 |
| isVoiced | 是否包含浊音 |
| normalizedKana | 规范化假名 |
| source | 单词来源 |
| confidence | 数据可信度 |

---

## 5.2 假名规范化

在比较两个单词之前，必须进行规范化处理。

处理规则：

1. 统一全角、半角字符。
2. 统一平假名、片假名的内部比较形式。
3. 统一 Unicode 字符形式。
4. 去除无意义空格。
5. 保留长音信息。
6. 保留促音信息。
7. 保留拨音信息。
8. 保留拗音结构。
9. 保留浊音与半浊音信息。
10. 不得在规范化过程中丢失发音差异。

例如：

```text
カイシャ → かいしゃ
会社的读音 → かいしゃ
```

平假名和片假名可以在内部转换为统一的比较形式，但不能在最终显示时丢失原始单词形式。

# 6. 干扰项生成策略

干扰项必须由多个策略共同生成。

每个候选词必须记录其来源规则，以便进行质量分析和后续优化。

## 6.1 R01：发音相似生成

寻找与目标词发音接近的单词。

比较因素包括：

- 音素相似度
- 辅音相似度
- 元音相似度
- 发音位置
- 清音与浊音
- 长音与短音
- 促音与非促音
- 拗音结构
- 拨音位置
- 音节顺序

示例：

```text
目標：かいしゃ

候选：
かいしゃ
かいしゃく
かいし
かいしゃい
```

候选仅为算法概念示意。

必须通过真实单词库进行校验，禁止直接将拼接出来的假名作为有效单词。

---

## 6.2 R02：假名结构相似生成

根据假名组成结构寻找相似单词。

主要比较：

- 假名长度
- 相同字符数量
- 字符位置
- 假名序列
- 相邻字符变化
- 拗音结构
- 词尾结构

例如：

```text
かいしゃ
かいしゃく
かいしゃい
```

优先寻找仅有少量字符差异的真实单词。

字符结构相似度不能作为唯一评分依据。

---

## 6.3 R03：长音混淆

寻找长音和非长音之间容易混淆的词。

例如：

```text
こうこう
ここ
ここう
```

必须根据实际单词库判断这些词是否存在、读音是否正确，以及是否具有可用的词义。

长音差异属于重要混淆特征。

---

## 6.4 R04：促音混淆

寻找包含促音与不包含促音的相似词。

例如：

```text
きて
きって
```

重点比较：

- 是否存在促音
- 促音位置
- 促音前后的辅音
- 单词整体长度
- 发音节奏

---

## 6.5 R05：浊音与清音混淆

寻找清音、浊音或半浊音差异较小的单词。

重点比较：

- か / が
- さ / ざ
- た / だ
- は / ば / ぱ

示例：

```text
かき
がき
```

此规则仅用于寻找真实词汇候选，不能因为只差一个字符就直接判定为高质量干扰项。

---

## 6.6 R06：拗音混淆

寻找拗音和普通假名组合之间容易混淆的单词。

重点比较：

- きゃ / きや
- きゅ / きゆ
- きょ / きよ
- しゃ / しや
- しゅ / しゆ
- ちょ / ちよ

必须正确识别日语拍音结构。

例如：

```text
きゅ = 1拍
きゆ = 2拍

きゅう = 2拍
きゆう = 3拍
```

不能简单使用字符数量代替拍数计算。

---

## 6.7 R07：语义相似生成

根据单词中文含义寻找相近词。

例如目标词属于：

```text
学习
学校
老师
学生
课程
考试
```

可以优先从学习、教育等相关类别寻找干扰词。

但必须注意：

**语义相关不等于高混淆。**

如果四个单词意思完全不同，用户可以通过中文语义轻松排除，则该题可能没有测试价值。

语义候选应当用于辅助生成，而不是单独决定干扰项。

---

## 6.8 R08：同类别混淆生成

从同一语义分类中寻找单词。

例如：

```text
交通类：
電車
地下鉄
駅
切符
飛行機
```

或：

```text
饮食类：
水
お茶
コーヒー
牛乳
```

同类别候选的价值在于降低明显排除的可能性。

但同类别单词如果发音、结构和词义差异过大，仍然不能作为高混淆度候选。

---

## 6.9 R09：个人错误生成

根据用户历史学习记录寻找用户容易混淆的单词。

例如：

用户历史：

```text
かいしゃ → 多次错误
かいしゃ / かいしゃく → 混淆
```

系统应优先将真实存在且符合题目条件的相关单词纳入候选池。

个人错误优先级高于一般词库推荐，但不能突破合法性校验。

---

# 7. 混淆度评分模型

系统需要计算目标单词与干扰词之间的混淆度。

## 7.1 评分维度

| 维度 | 符号 | 权重 |
|---|---|---:|
| 发音相似度 | P | 40% |
| 假名结构相似度 | K | 25% |
| 语义相似度 | S | 20% |
| 个人混淆度 | M | 15% |

初始综合评分公式：

```text
ConfusionScore =
    0.40 * PhoneticSimilarity
  + 0.25 * KanaStructureSimilarity
  + 0.20 * SemanticSimilarity
  + 0.15 * PersonalConfusion
```

所有评分统一为 0～1。

---

## 7.2 发音相似度 P

发音相似度需要考虑：

- 音素编辑距离
- Mora 编辑距离
- 元音匹配程度
- 辅音匹配程度
- 长音差异
- 促音差异
- 拗音差异
- 浊音差异
- 拨音差异
- 音调差异（后续版本）

建议采用加权特征距离：

```text
PhoneticDistance =
    0.25 * MoraEditDistance
  + 0.20 * VowelDistance
  + 0.20 * ConsonantDistance
  + 0.15 * LongVowelDistance
  + 0.10 * GeminateDistance
  + 0.10 * SpecialSoundDistance
```

将距离转换为相似度：

```text
PhoneticSimilarity = 1 - PhoneticDistance
```

所有距离必须归一化到 0～1。

实际实现应采用适用于日语拍音结构的距离算法，不能直接使用普通字符串编辑距离作为唯一依据。

---

## 7.3 假名结构相似度 K

比较：

- 假名长度
- 字符相似度
- 相同字符位置
- 字符顺序
- 假名变化数量
- 拗音结构
- 词尾结构

建议：

```text
KanaStructureSimilarity =
    0.30 * NormalizedKanaEditSimilarity
  + 0.25 * PositionSimilarity
  + 0.20 * LengthSimilarity
  + 0.15 * MoraStructureSimilarity
  + 0.10 * SpecialKanaSimilarity
```

注意：

假名结构相似度与发音相似度存在部分重叠。

因此在后续模型训练或实际数据校准中，需要避免对同一特征重复加权过高。

---

## 7.4 语义相似度 S

语义相似度应当基于：

- 中文释义
- 日语词义
- 词性
- 语义类别
- 使用场景
- 同义词关系
- 反义词关系
- 近义词关系

建议语义评分分级：

| 关系 | 评分建议 |
|---|---:|
| 同义词 | 0.95 |
| 近义词 | 0.85 |
| 同一语义类别 | 0.65 |
| 同一使用场景 | 0.45 |
| 弱相关 | 0.20 |
| 完全无关 | 0.00 |

评分只是初始参考，需要实际测试调整。

---

## 7.5 个人混淆度 M

根据用户历史表现计算。

推荐考虑：

- 错误次数
- 最近错误次数
- 连续错误次数
- 错误选项与正确选项的关联
- 最近一次错误时间
- 正确次数
- 总测试次数
- 掌握程度

建议初始模型：

```text
PersonalConfusion =
    0.35 * ErrorRate
  + 0.30 * RecentErrorRate
  + 0.20 * ConsecutiveErrorScore
  + 0.15 * ForgettingScore
```

其中：

```text
ErrorRate = 错误次数 / 总测试次数
```

最近错误应采用时间衰减机制，避免过早发生的错误长期影响题目生成。

用户数据不足时：

```text
PersonalConfusion = 0
```

或使用系统默认中性值，不得伪造学习记录。

# 8. 候选词过滤

所有候选词必须经过过滤。

## 8.1 必须过滤的情况

以下候选直接排除：

1. 候选单词与目标单词相同。
2. 候选词不存在于有效词库中。
3. 候选读音不正确。
4. 候选中文释义缺失。
5. 候选与正确答案完全相同。
6. 候选重复。
7. 候选存在多个读音，且当前读音无法确定。
8. 候选与目标词存在相同答案语义，容易导致多个正确答案。
9. 候选不适合当前学习阶段。
10. 候选数据可信度不足。
11. 候选无法提供题目所需的音频资源（当题目要求音频时）。
12. 候选词本身不符合当前题型。

# 9. 混淆度等级

候选词筛选采用混淆度分级。

| 分数 | 等级 | 使用建议 |
|---|---|---|
| 0.90～1.00 | 极高 | 需人工审查，可能过于接近 |
| 0.80～0.90 | 高 | 优先用于高难度题 |
| 0.65～0.80 | 中高 | 优先用于普通混淆题 |
| 0.50～0.65 | 中 | 可作为补充 |
| 0.30～0.50 | 低 | 普通练习可使用 |
| 0.00～0.30 | 极低 | 高混淆题禁止使用 |

以上分数是工程评分，并不代表真实人类混淆概率。

# 10. 四选一组合优化

算法不能简单选取评分最高的三个候选词。

因为可能出现：

```text
正确答案：A

错误答案：
B：发音高度相似
C：发音高度相似
D：发音高度相似
```

虽然三个候选均具有高混淆度，但题目可能缺乏差异性。

因此需要进行组合优化。

## 10.1 组合约束

最终三个错误选项必须满足：

1. 三个选项均为合法单词。
2. 每个选项均达到最低混淆度阈值。
3. 至少包含两种不同的混淆类型。
4. 优先包含三种不同混淆类型。
5. 不允许三个候选完全来自同一种规则。
6. 不允许存在明显无关选项。
7. 不允许形成明显的答案提示。
8. 不允许多个正确答案。
9. 不允许三个候选都过于简单。
10. 不允许因个人错误记录而重复生成同一组题目。

---

## 10.2 组合评分

```text
CombinationScore =
    0.45 * AverageConfusionScore
  + 0.20 * RuleDiversity
  + 0.15 * DifficultyMatch
  + 0.15 * PersonalizationScore
  + 0.05 * NoveltyScore
```

说明：

- AverageConfusionScore：三个错误选项平均混淆度。
- RuleDiversity：混淆类型多样性。
- DifficultyMatch：与当前题目难度匹配程度。
- PersonalizationScore：与用户历史错误关联程度。
- NoveltyScore：题目及候选组合的新颖程度。

---

# 11. 难度控制

系统支持五种难度等级。

## L1：基础

特点：

- 选项差异明显
- 单词词义清晰
- 适合初学者
- 混淆度较低

## L2：简单混淆

特点：

- 至少一个发音相近单词
- 至少一个结构相近单词
- 其他选项允许语义相关

## L3：标准混淆

特点：

- 三个错误选项均具有一定混淆度
- 至少两个选项与目标词发音相近
- 语义差异不能过于明显

## L4：高混淆

特点：

- 三个错误选项均为高质量候选
- 优先发音接近
- 优先假名结构接近
- 优先同类别或相似语义
- 选项组合经过优化
- 不允许明显无关选项

## L5：极限混淆

特点：

- 三个错误选项均具有极高混淆价值
- 尽可能覆盖不同混淆维度
- 优先个人错误记录
- 选项差异细微
- 必须保证单一正确答案
- 不能因难度过高而降低题目合法性

---

# 12. 难度筛选规则

建议初始阈值：

| 难度 | 单个干扰项最低混淆分数 |
|---|---:|
| L1 | 0.30 |
| L2 | 0.45 |
| L3 | 0.60 |
| L4 | 0.72 |
| L5 | 0.80 |

这些阈值仅作为初始工程参数。

实际系统必须根据生成质量、用户正确率、错误选项选择分布进行调整。

当候选不足时：

1. 扩大候选搜索范围。
2. 追加其他混淆规则。
3. 扩展语义类别。
4. 检查个人错误词库。
5. 适当降低候选最低分数。
6. 降低当前题目难度。
7. 如果仍不足，则返回候选不足。

禁止直接使用低质量单词凑齐四个选项。

- 最近使用的混淆规则

- 用户已经掌握的单词

重复惩罚：

```text
RepeatPenalty =
    RecentTargetPenalty
  + RecentDistractorPenalty
  + RecentCombinationPenalty
```

在候选充足的情况下，优先避免重复。

当候选不足时允许重复，但不得因此使用不合法单词。

# 16. 算法伪代码

```text
function GenerateVocabularyQuestion(targetWord, user, difficulty):

    # 1. 校验目标单词
    validateTargetWord(targetWord)

    # 2. 解析目标单词特征
    targetFeatures = analyzeVocabulary(targetWord)

    # 3. 生成干扰候选池
    candidates = generateCandidates(
        targetFeatures,
        rules = [
            PHONETIC_SIMILARITY,
            KANA_STRUCTURE,
            LONG_VOWEL,
            GEMINATE,
            VOICING,
            CONTRACTED_KANA,
            SEMANTIC_SIMILARITY,
            CATEGORY_SIMILARITY,
            PERSONAL_ERROR
        ]
    )

    # 4. 候选合法性过滤
    candidates = filterValidCandidates(
        candidates,
        targetWord
    )

    # 5. 计算混淆度
    for candidate in candidates:

        candidate.confusionScore =
            calculatePhoneticSimilarity(targetWord, candidate) * 0.40
          + calculateKanaSimilarity(targetWord, candidate) * 0.25
          + calculateSemanticSimilarity(targetWord, candidate) * 0.20
          + calculatePersonalConfusion(user, targetWord, candidate) * 0.15

    # 6. 根据难度过滤
    candidates = filterByDifficulty(
        candidates,
        difficulty
    )

    # 7. 排除近期重复
    candidates = applyRepeatPenalty(
        candidates,
        user
    )

    # 8. 优化三个错误选项的组合
    distractors = optimizeCombination(
        candidates,
        count = 3,
        ruleDiversity = true,
        highConfusion = true
    )

    # 9. 候选不足处理
    if distractors.size < 3:
        return handleInsufficientCandidates(
            targetWord,
            user,
            difficulty
        )

    # 10. 生成四个选项
    options = [
        targetWord,
        distractors[0],
        distractors[1],
        distractors[2]
    ]

    # 11. 随机打乱选项顺序
    shuffle(options)

    # 12. 最终校验
    validateQuestion(
        targetWord,
        options
    )

    # 13. 返回题目
    return buildQuestion(
        targetWord,
        options,
        difficulty
    )
```

# 19. AI 实现约束

当 AI 读取本规范并执行实现时，必须遵循以下规则：

1. 不得擅自修改算法核心评分结构。
2. 不得使用普通随机抽取代替混淆候选生成。
3. 不得通过随机拼接假名生成错误单词。手写选假名见 3.2，只允许列出的那几类发音变化。
4. 所有干扰项必须来自合法词库。手写选假名见 3.2，干扰读音可以不是词库里的词。
5. 必须保留候选生成来源。
6. 必须保留候选混淆评分。
7. 必须支持难度控制。
8. 必须支持候选合法性过滤。
9. 必须支持组合优化。
10. 必须支持题目质量验证。
11. 候选不足时不得强制凑数。手写选假名见 3.2，用同一套发音规则补齐，不用无关假名。
12. 不得将语义相关等同于发音混淆。
13. 不得将字符相似等同于真实发音相似。
14. 不得将算法评分描述为真实人类混淆概率。
15. 不得将多个正确释义的单词放入单一答案题目中，造成答案歧义。
16. 不得因为用户答错就直接认定用户永久不掌握该单词。
17. 所有算法参数应支持配置。
18. 评分计算应具有可追踪性。
19. 相同输入和相同配置应尽可能得到可复现结果。
20. 后续优化不得破坏题目正确性。

# 23. 最终设计原则

本系统不是随机单词四选一系统。

它是一个基于日语单词特征、发音结构、假名结构、词义关联以及用户学习行为的混淆题生成引擎。

整个算法必须始终遵循：

**第一，正确性优先于混淆度。**

**第二，真实单词优先于算法拼接。**

**第三，有意义的混淆优先于随机错误。**

**第四，组合质量优先于单个候选评分。**

**第五，实际学习效果优先于理论评分。**

**第六，用户错误数据优先用于个性化，而不是改变语言本身的规则。**

最终目标是让每一道题都能有效检验用户是否真正掌握日语单词，而不是通过明显的选项差异轻松猜出答案。
